# 存活与终止治理（liveness）

> **术语**：「**失联**」＝ 一方**停止推进**，使他方**无法据现有证据预期后续推进**。
> **本文件只写「故障类型 → 对策」与可迁移机制；不含任何具体轮次的人物、时间、消息 id。**

## 1. 证据边界（不得越界）

- 共享文件**只能**证明：① 某些事项**停止推进**；② 当事人的**自述**；③ **实际工具结果**；④ **使用者的反馈**；
- **不能**证明客户端、网络或会话的在线/离线：**无直接证据时标「未知」**；
- **本架构不保证跨会话后台唤醒** → **等待本身不保证后续推进**；但**活跃会话仍可继续执行工具操作**，**不得把「等待」判定为「结束」**；
- **「无新写入」只能说明未观察到新写入**，不能证明在线、离线或失败。

## 2. 故障类型 → 对策（一张表）

| 故障类型 | 机制 | 对策 |
| --- | --- | --- |
| **不保证跨会话唤醒** | 等待没有推进力 | 有依赖时**用实际等待工具**、短时等待后**读增量**；等待须写明**对象 + 替代工作 + 恢复条件** |
| **把「汇报」当「完成」** | 汇报是给使用者的输出，被当成给协作的推进 | **阶段完成 ≠ 全轮完成**；**本人 FIN 与全轮结束分开写** |
| **承诺的动作没登记/没回读** | 「我声明要做」这件事本身没有载体 | **宣布即登记**进未完成事项表；**操作与校验用不同判据**；**写完回读** |
| **单点叠加** | 读取方/写入者/提交方/记录者叠在一人身上 | **拆分单点**；给出**结构性机制**（登记表 / 书面 FIN / 写入权交接），而不是只靠自觉 |
| **「无新写入」被当成状态** | 把「未观察到」当成结论 | **只承认可核对证据**；其余标「未知」 |
| **承诺无法验证** | 「保持在线」没有载体、不会过期 | 用**在场租约**（只表示自报 + 预期） |
| **客户端自带「任务完成/结束」入口** | 语义等同结束，诱导把「本阶段可自主事项做完」误判为「全轮完成」 | **客户端结束动作不得替代书面 FIN**：**先写 FIN 再调用** |
| **越权写入 / 未同步** | 不走显式交接就改文件，或改了源没同步副本 | **显式交接**；**未同步全部安装位置 = 未完成**；越权产出**保留不回滚**，由唯一写入者**整合** |

## 3. 结束前检查（**这是提醒，不是拦截**）

**三问**（注意：**触发方向不同，不能统一写成「任一否」**）：

| # | 问题 | 触发「不得停手」的答案 |
| --- | --- | --- |
| 1 | 我声明的动作都执行了吗？ | **「否」** |
| 2 | **有没有人在等我？** | **「是」**（先回应或**显式移交**） |
| 3 | 不依赖他人的工作做完了吗？ | **「否」** |

**常设义务也逐条核对**（不依赖「我是否登记过」）：工作文件是否过大需切换、技能/配置是否已同步全部副本、可选的聊天记录是否已归档并清空、**每轮结束是否已调整并归档文件夹内容（归档 + 更新导航 + 回读）**、要求文件是否已查看并登记变更、是否已复盘并把修正写回约定。

**⚠️ 能力边界**：以上可以写成**静态自检脚本**，但**它只有提示能力、没有硬拦截能力**；**真正自动阻止结束需要客户端/运行器把检查接到「结束入口」**。**PASS 只代表「静态提示通过」，不等于已读、不等于审查通过、不等于已归档、不等于全轮完成。**

## 4. 读取游标（防「以为读过」）

- 用**唯一消息 id** 作游标，**不要**用文件 mtime，**更不要**用「我自己最后一条发言」（在未读消息之后再发一条就能把告警消掉）；
- 消息头解析要**同时支持分钟级与秒级**两种规范格式；
- 判定：游标 ≠ 已观察到的最后一条消息 id → **可能有未读增量 → 先读**。

## 5. 终止流程（**只保留一套**）

1. **本人必要工作与必要审查完成、无必须由本人回应的未处理请求** → 可写**个人 `FIN`**（**只声明本人准备结束本阶段**，不表示立即结束会话）；
2. **全体实际参与者均明确准备结束** → **唯一记录者**执行**共享归档（仅一次）**：写入 → **回读核对** → 才清空；并**更新导航**、按实际路径封存工作线程；
3. **最终 `CONFIRM`** 宣告**全轮结束**；
4. **各会话才结束**。

**要点**：
- ⚠️ **区分「个人整理」与「共享归档」**（这是两个不同动作，不要混写）：
  - **个人整理**：本人**可以在写自己的 FIN 之前独立完成**——自己的交付与自己在意的文件整理，**不等他人 FIN**（否则形成死锁）；
  - **共享归档**：**必须等所有实际参与者准备结束后**，由**唯一整理者执行一次**（写入 → 回读核对 → 才清空）；**其余方不重复搬动共享文件**；**不得提前清空仍有人在发言的记录**。
- **未满足的审查只登记等待**，**不得以「请求已发出」代替审查通过**；
- **OPEN 表不必清空历史完成行**。

## 6. 写入权与交接

1. **提醒 ≠ 授权**：任何一方（含看门狗）的提醒/催促**不自动转移写入权**；
2. **超时 ≠ 同意**：**没有回复不等于默许**；超时只能记「暂搁置」；
3. **交接程序**：① **原执行者显式释放** + ② **接任者 ACCEPT**（或 ③ **使用者明确指派**）；开始时须确认**进行中的操作与锁状态**；
4. **「继续自动推进」≠「改写入权」**；**未同步 = 未完成**；
5. 发现越权写入：**保留其内容作为证据**，由**唯一写入者整合**（不覆盖不回滚）。

## 7. 传播与效力（区分两件事）

- **使用者的决定按其真实指令生效**——**授权效力不取决于任何一方是否回执**；
- **传播确认**需要三步：落地到**所有活文件** → **广播并显式要求回执** → **收到回执或等价读取证据**；**在此之前只视为「传播确认尚未完成」**；
- **未确认方不得假设对方已读**，但**不得据此否定使用者授权的效力**——**回执不是对使用者决定的否决权**。

## 8. 汇总/归纳的前置条件（防过早收敛）

- **汇总/归纳是收敛动作，不是及时汇报**：**只有他方必要确认齐备后**才可发布**收敛性结论**；
- 在此之前只能出**「阶段性草稿」**，并标注：`阶段性 · 未收敛 · 可能过时` + **生成时间** + **依据版本/指纹** + **未确认项** + **收敛条件**；
- **不得把未确认内容写成结论**；**收敛前不得使用「该轮结果 / 最终 / 已确认」这类措辞**（标注的诚实性与内容同等重要）。

## 9. 边界（防自我拔高）

- **不是 BFT**：无签名、无法定人数、无恶意节点模型；面向**「诚实但会停手、会犯错」**的参与者；
- **「只追加」不是 CRDT**：不保证交换律与收敛，顺序仍靠**锁 + `id`/`reply_to`**；
- **可称「借鉴容错思想的共享文件协作原型」**；**未验证**拜占庭故障模型、容错阈值、共识正确性或 CRDT 收敛；
- 可能的故障**不止「崩溃停止」**，还包括**误写、越权、提前停止、未完成操作**，**不宜统称 crash fault**。
