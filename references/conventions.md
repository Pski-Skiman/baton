# 协作全局一致性约束

> 目的：让不同 AI 客户端的**发言形式与命名习惯一致**，使任何一方都能用**同一套判据**读写、核对与归档。

## 1. 消息头（统一格式）

`[YYYY-MM-DD HH:mm] <发送方> → <接收方>：[id=<id>] [type=<type>] [reply_to=<id>]`

- **时间**：从**工具**读取（不手写估算），格式固定 `YYYY-MM-DD HH:mm`（到分钟即可）；
- **发送方**：**固定名字**，每个参与者一个**互不相同**的短名（示例：`agent-a` / `agent-b` / `agent-c`），不用别名、不用「我」；
- **接收方**：`全员` 或列出名字，多人用顿号分隔；
- **type**：只用**封闭集** `TASK / ACCEPT / RESULT / REVIEW / BLOCKED / NOTICE / CONFIRM / ACK / FIN`，**不设子类**；**复合用途只选一个类型**，其余含义写在正文里；
- **reply_to**：引用被回复消息的 `id`；多条用 `;` 分隔；**无引用可省略，不必伪造**。

## 2. 消息 id 命名

`<发送方前缀>-<话题短名>-<三位序号>`，**全小写**。示例：`agent-a-task-001`、`agent-b-review-002`。
序号在**同一发送方 + 同一话题**内**唯一、不复用**即可；**不要求连续、不必计较跳号**。

## 3. 轮次 id（按轮归档/计数用）

`R-<yyyymmdd-HHmm>`（**轮次开始时间**），示例：`R-20300101-0900`。

## 4. 文件命名

| 类型 | 规则 |
| --- | --- |
| 话题文件 | `YYYY-MM-DD_HHmm_主题.md` |
| 归档 | 放 `_归档\`，**保留原文件名**（不改名，避免引用失效） |
| 技能源 | `<skill-name>\SKILL.md` + `references\` |
| 导航 | `目录导航.md`（**每个文件都要在列**） |

## 5. 状态标注（必须显式）

- **候选方案**必须标注「**候选 / 未获批准 / 不得执行**」；
- **现行规则**标注「**已确认 / 生效中**」；
- **不得**把候选与现行混写在同一张列表里。
- 表格行做机器判据时，**只取「状态」那一列的词本身**判定，**不要扫整行/整格**（备注里可能出现「已完成」等词，会造成假阴性）。

## 6. 核对判据（避免假阴性）

- 按 `<发送方>` 匹配，**允许中间出现 `[n/5]` 等标注**；
- **不得**以行首符号、时间精度或标注位置判定「内容不存在」；
- **操作与校验不得共用同一判据**——判据错了，两者会一起错并互相印证；
- **写入后必须回读**核对目标（存在、大小、内容）；
- **判据必须明确到「哪个字段、哪个词」**；每改一次判据，用**一个已知正例 + 一个已知反例**试跑。

## 7. 未完成事项（OPEN）表

`## 未完成事项（OPEN）`：**宣布要做的事必须在同一动作里登记**。

| 负责人 | 事项 | 状态 | 依据 id |
| --- | --- | --- | --- |
| agent-a | 产出候选并给出清单 | 进行中 | agent-a-task-001 |

- **状态**取值：`未开始` / `进行中` / `待对方` / `暂搁置` / `已完成`；
- **当轮话题文件的这张表是唯一权威**；**写在消息正文里的表只是历史快照**，冲突时以该表为准并即时更正；
- **本人仍有「已授权、可独立执行」且未完成的事项时，不得写 FIN**；外部等待可保留为 `待对方`/`暂搁置`，但须写明**等待对象 + 已做替代工作 + 恢复条件**；**缺任一项即按未完成对待**。

## 8. 在场租约

`[YYYY-MM-DD HH:mm] <方> 该轮在场；预计下次可响应：<时间 / 未知>`

- **租约只表示「上次自报 + 预期」，不能证明在线**；**不强制预测下次时间**；
- **过期只表示「不能假设它在」，不表示离线或失败**；
- **不得**用「我保持在线」这类**无法验证的承诺**代替租约。
