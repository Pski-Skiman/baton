# 接力棒 · Baton —— 人类指挥的多 AI 异步协作协议（共享文件夹）

> ⚠️ **先说局限（最重要）**
>
> 这**不是**自动化多智能体框架。它是一套**给人用的、异步的、靠唤醒的**协作协议：
> - **没有**后台轮询、跨会话唤醒或自动续跑；推进依赖人类在各客户端之间唤醒各方；
> - **「等待」不保证后续推进**（但**活跃会话仍可继续执行工具操作**，不能把等待直接判定为结束）；
> - 「对方是否在线」**无法从共享文件夹推断**——「没有新写入」只能说明**未观察到**新写入；
> - 因此本方法里的「超时」**一律不作为失败判据**，**超时也不能代替必要审批**。

## 它解决什么问题

多个 AI 客户端各自独立运行、互不可见，但**服务同一个使用者**。它们需要一个共享的通信面。直接「往文件夹里丢留言」会立刻撞上四类问题：

1. **并发写**：两方同时改同一个文件 → 互相覆盖；
2. **不知道对方收到没有**：写完就结束，无法确认；
3. **重复劳动**：同一任务被同时分配给多方，各自做一遍；
4. **无法追责/无法复盘**：谁改了什么、依据是什么，事后查不清。

本项目给出一套**只追加 + 原子锁 + 消息 id + 独立审查 + 确认绑定字节**的做法，并记录实测踩坑。

## 核心设计（详见 `SKILL.md`）

- **信道**：一个话题一个文件，**只追加不覆盖**，UTF-8 无 BOM；
- **并发**：锁文件**原子创建**（`CreateNew`），**禁止「先判断再创建」**；等待与推理一律在锁外；
- **消息**：`[时间] 发送方 → 接收方：[id=…] [type=…] [reply_to=…]`，**类型只用封闭集**；**已读 ≠ 接受，交付 ≠ 验证通过**；
- **顺序**：`id` + `reply_to` 决定因果，**不用文件 mtime 给文件内部消息排序**；
- **可选可靠传输**：类 TCP 的 SYN/序号/`ack`/重传/FIN，**默认关闭**；只在双方都声明轮询并约定响应窗口时启用；
- **分工**：**一个执行者 + 独立审查者**；同一文件只有一个写入者；被指定方须 ACCEPT 并确认前置条件；
- **存活与终止**：**阶段完成 ≠ 全轮完成**；**宣布要做的事必须同时登记**；**结束前必须自检**；**显式交接**（提醒≠授权／超时≠同意）；
- **一致性**：消息头、id 命名、文件名、状态标注统一；**候选与现行必须显式区分**；
- **git**：唯一写入者**仅限写操作**（读操作可多人并行）；**`commit` 与 `push` 都需真实授权**，他人建议不能代替；
- **确认绑定字节**：确认时附上被确认范围的 **SHA-256**，复核方独立复算。

## 实测踩坑（可复现）

- **双引号 here-string 吃反引号**：反引号加 `a` → U+0007、加 `r` → U+000D；反引号加非转义字符会**静默吃掉反引号**。→ 用**单引号 here-string** 或字面方式构造正文。
- **单引号 here-string 不插值**：`$变量` 会**原样写进文件**（实测把 `$时间戳`、`$路径` 当字面量写进了记录）。→ **构建正文时二者必居其一：双引号防反引号、单引号防变量；写完必须回读确认没有残留 `$` 字面量。**
- **指纹范围边界**：同一段文本**含不含末尾换行**会得到两个不同哈希。→ 确认时必须写清边界。
- **回收站不能按文件名搜**：会被重命名；须查 `$I` 元数据里的原路径。
- **验证手段自身要自检**：真实犯过的一类假结论——`[int]` 是四舍五入而非截断；函数名撞 Shell 别名导致「空 == 空」被判一致；`Sort-Object -Unique` 单元素返回字符串；**正则非法被静默跳过**（模式从未被检查却打印「全部为 0」）；**用「长度变化」判断「是否改动」**（等长替换导致文件根本没写盘）。→ **每次改判据，用一个已知正例 + 一个已知反例试跑。**
- **并发写会丢更新**：非原子的「读—改—写」会吞掉他人的追加。→ 追加与「读—改—写」是两种操作，后者必须整体在锁内完成。
- **客户端可能自带「任务完成 / 结束」入口**：其语义等同结束，会**诱导提前停手**（属**工具可供性**问题，不是态度问题）。→ **客户端结束动作不得替代书面 FIN**。
- **越权写入**：不走显式交接就改文件、且**未同步全部安装位置** → 多副本不一致。**未同步＝未完成**；已发生时应**保留产出、由唯一写入者整合**（不覆盖不回滚）。
- **指标粒度**：「声明值只到分钟」不能说「时间完全一致」；「无 BOM / 无 U+FFFD」不等于内容未损坏。
- **删除安全**：区分「历史」与「垃圾」；默认可恢复归集；永久删除须**记录使用者授权来源**，且**使用者的直接授权优先于 AI 意见**。

## 快速上手

1. 建一个共享文件夹，放一份**使用者要求文件**（AI 只读）；
2. 把本仓库内容放到 **`<skills-root>/ai-collaboration/`**（即 `SKILL.md` + `references/`；各客户端 skills 根目录不同，**请在你自己的环境确认**）；**注意：平台规则与使用者的直接指令优先于**协作目录里的「要求文件」；
3. 第一次协作先约定：信道文件名、锁文件名、消息类型集、是否启用类 TCP、**未完成事项表与看门狗**、**在场租约格式**；
4. 每轮结束**各自简短复盘**，把修正写回约定文本；并**调整、归档文件夹内容**（归档当轮话题文件与聊天记录、更新导航、核对无失效引用）。

> **可选扩展**：如需「AI 间自由聊天室」这类扩展，**由项目自行约定**（本仓库默认不含其细则）。

## English summary

A human-in-the-loop, asynchronous **multi-AI collaboration protocol over a shared folder**: append-only channel, atomic lock, message ids with `reply_to`, optional TCP-like reliability, single-writer + independent reviewer, explicit handover, and a liveness/termination discipline ("stage done ≠ round done"; a client-side "task complete" action must **not** replace a written FIN). Not an autonomous multi-agent framework: there is no background polling and no cross-session wake-up.
