# 接力棒 · Baton 0.3

让多个独立Agent通过同一共享文件夹分工、交付和独立审查。Baton是一份可安装的Agent Skill，加上三个可选的Python辅助脚本。适合跨客户端协作、无上下文接手、避免多人覆盖和处理收尾死循环；一次对话能完成的小任务无需启用多人协议。

## 功能与入口

| 部分 | 用途 | 使用时机 |
| --- | --- | --- |
| [SKILL.md](SKILL.md) | 加入、写入归属、消息、证据和交接规则 | Agent加入或恢复时必读 |
| [references/](references/onboarding.md) | 操作细节与边界 | 按SKILL链接触发读取 |
| `scripts/quiet_window_watch.py` | 对所列文件做有界安静窗口采样 | 未完成时主动让出且项目要求测窗口 |
| `scripts/shutdown_plan.py` | 保存、取消、续期和检查手动提醒计划 | 需要持久化可取消计时计划 |
| `scripts/attribution.py` | 判定本方追加、他方活动或未知变化 | 内部库模块，不提供命令行 |

脚本不执行关机、不运行Agent、不唤醒其它客户端。窗口满足和计时到期只是事实，不是结束许可。正常完成后不额外等五分钟。

## 使用

1. 把本仓库的`SKILL.md`、`references/`、`scripts/`一起放到客户端的`<skills-root>/ai-collaboration/`，保留相对结构；也可在项目内直接指定此SKILL.md。
2. 明确真实共享工作目录，建立入口和一份本轮事项表，指定写入者。技能目录放规则与工具，共享目录放任务和话题，二者可以分开。
3. 各方先读现场并接受具体任务，实现方验证产物、审查方独立核对、记录者更新事项并交接。

不同客户端按自己的实际技能导入方式操作；本发布未代你安装或验证各客户端导入。写TASK文件不会自动唤醒对方。

先读[SKILL.md](SKILL.md)，再按任务触发读取参考。技能不是当前任务记录：新加入者仍需读真实项目入口、当前事项和定向消息。共享目录文件名可沿用中文约定或由项目映射。

无需运行Python也能使用协作规则；可选脚本需要Python 3.9+，只用标准库。3.9为语法检查下限，运行验证以CHANGELOG实际环境为准。以下验证从完整仓库根目录运行，需要仓库的tests/与VERSION等文件，精简安装包不包含测试时不能照此运行：

```
python -m unittest discover -s tests -v
python scripts/validate_package.py
```

## 能做与限制

原子锁、单一写入者、追加消息、范围明确的确认与交接可以减少覆盖、重复执行和误判完成。后台检测只识别采样范围内的变化；计划只记录和检查，不执行关机、不调度模型、不保证无人值守推进或跨会话自唤醒。正常完成不额外等待五分钟；未完成时主动让出须按项目规则核对前提。

等待外部任务时，不把客户端的完成标记当作等待方式；只在承诺和必要交付核销后结束。Skill不能硬拦截客户端出口，后台观察也不能恢复模型判断。

Git版本不含协作聊天、用户要求原文、个人资料、状态、锁或私有记忆。历史现场可以本地留档；发布规则只保留可复用做法。

版本：`VERSION`；变更与验收边界：[CHANGELOG.md](CHANGELOG.md)。源技能与安装副本分开管理，不能将发布成功称为所有客户端已安装。
