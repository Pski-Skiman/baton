# 故障排查与升级

| 现象 | 先核对 | 处理 |
| --- | --- | --- |
| 只有SKILL但相对参考找不到 | 安装结构 | 保留references和scripts同级，不只复制单文件 |
| 不知道谁在干什么 | 当前入口、本轮ID、唯一事项表 | 读取现场，不从最新文件或旧FIN猜全局状态 |
| 发TASK没有回应 | 对方是否实际被唤醒、是否ACCEPT | 记录未接受，继续独立工作；没有回应不等于离线或失败 |
| 多人都在改同一文件 | 当前轮写入归属与锁 | 先明确唯一写入者，审查方只读；不删除他方锁 |
| WAITING但退出码是0 | JSON事件 | 命令执行成功不代表期限已到 |
| TIMER_ELAPSED但仍有人在等 | 具体请求、purpose和所列文件 | 继续处理请求；提醒或快照比较不替代完成检查 |
| STATE_UNREADABLE | 保存文件结构、版本和快照 | 保留原件，人工核对；不把损坏文件当空计划 |
| STATE_OWNER_MISMATCH / STATE_PATH_OUTSIDE_ROOT | who和恢复路径 | 保留原件，确认正确身份/目录；不通过放宽校验绕过 |
| READ_ERROR / UNREADABLE | 文件路径、编码和权限 | 恢复可读载体后重新核对，不据缺失判安静 |
| STALE_LOCK_SUSPECT | 持有者与进行中操作 | 超龄不等于进程已死；人工确认且获授权后才清理 |
| 文档中文乱码 | UTF-8读取入口 | 显式UTF-8；Python可使用`python -X utf8 ...` |
| 当前Skill与全局安装副本冲突 | 路径、VERSION和内容指纹 | 使用本轮明确入口，不从旧副本继承角色；另行授权同步安装 |

## 从0.2升级

0.3强化了恢复计划的结构、身份和路径校验。合法0.2计划继续按现有格式读取；损坏、缺字段或身份不匹配的状态被拒绝，不能自动重建。旧版其它`.state`目录不会迁移。

先保存当前任务和原安装包，确认没有进行中写操作，再在授权范围替换整个技能包并回读VERSION与相对链接。源码仓库更新不自动修改客户端安装。恢复协作还需读真实入口和本轮事项，不恢复旧FIN。

## 未验证与报告方式

现有行为回归覆盖本地临时目录和有限真实进程；没有承诺客户端导入、网络共享/跨平台锁、断电恢复或跨会话唤醒。报告问题请提供工具命令（脱敏路径）、版本、事件和退出码、预期与实际结果、最小可复现载体。不要上传真实Secret、完整用户聊天或私有记忆。
