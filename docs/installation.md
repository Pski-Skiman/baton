# 客户端安装与验证

源仓库更新、技能文件安装、客户端加载、实际持续等待是四件事，分别记录证据。技能规则不能硬拦截模型的最终答复；真实宿主续轮/唤醒需要该端接口和授权。

## 安装

安装 `ai-collaboration` 时保留SKILL.md、references、scripts、docs的相对结构；要在安装目录运行仓库测试/校验时还需完整tests、VERSION及仓库说明文件。安装同名技能前备份旧版本，只更新该技能，不改其它技能或全局设置。

| 客户端 | 技能目录/方式 | 验证 |
| --- | --- | --- |
| Codex | 已配置用户skills根目录（常用`~/.codex/skills`）；按本端配置核对 | 确认技能被发现；本会话显式读取新版入口，后续会话确认加载来源 |
| DeepSeek Harness | 已配置用户skills根目录（常用`~/.dsh/skills`） | 核对实际目录与本端技能发现，续轮能力另测 |
| WorkBuddy | 本端配置的skills目录，不能借他端路径推断 | 以该端工具/记录确认；旧会话未重新加载时不能声称生效 |
| GitHub Copilot | 个人`~/.copilot/skills`或`~/.agents/skills`；项目`.github/skills` | 优先选本端专用根；`.agents`可能被其它客户端一起扫描，不同时保留同名副本；确认本端加载来源 |
| 豆包 | 已知本地技能目录可存安装文件；“我的技能→上传技能”导入每个技能目录 | 目录自动扫描若未验证，就不能以复制完成代替UI导入 |

Copilot路径依据[GitHub官方技能说明](https://docs.github.com/en/copilot/concepts/agents/about-agent-skills)。其它端以真实配置和本端记录为准，不从品牌假定最小间隔、续轮或自动加载能力。

## 三层验收

1. **文件**：入口版本、SHA-256、UTF-8无BOM、相对链接和工具可运行。只声明已安装明确范围；无关旧文件不随意删除。
2. **加载**：让本端明确读取新版SKILL.md，报出“阶段交付不解除等待、先六项交接/状态再300秒检测、窗口不授予完成”的规则及当前任务。记录加载路径/时刻，不能只看文件存在。
3. **行为**：在仍有待处理回执时继续读取；新任务到达撤销收尾；未知变化/读取失败阻塞；全部前提满足后实跑300秒，再复核。临时目录测试不是客户端关闭重开实验。

未运行或已停止的客户端只能验收文件，等待其实际加载验证；豆包若需人工上传，提供准备好的自足目录/压缩包，不把上传代做宣称成功。`anti-interruption`包必须自带所需引用与工具，不依赖上传后能访问另一技能的私有目录。
