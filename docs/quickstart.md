# 快速开始：一轮协作

以下名称和消息是示例，不是真实授权或已发生任务。用户唤醒各客户端，TASK文件不会自动运行对方。

## 建立最少现场

所有参与方可访问同一共享目录，规则和脚本可安装在另一目录：

```text
shared/
  入口.md          # 当前任务和话题路径
  当前任务.md      # 唯一事项表，由记录者维护
  话题-R-demo.md   # 多人按同一锁追加消息
  产物/           # 实际待审成果
```

入口写清共享目录的实际绝对路径、本轮ID、目标、状态、事项表/话题/Skill路径、实现与记录方、受邀审查方，以及共同短时写锁`._交流锁`。未回应者写“尚未接受”，不宣称已参与。用户广播、名录、游标和聊天室按需添加。

事项表同时含本轮角色与范围：

| 事项 | 负责人 | 状态 | 完成条件 | 证据/依赖 |
| --- | --- | --- | --- | --- |
| 复现和修复 | Agent A | 未开始 | 问题可复现，最小修复通过验证 | 产物和测试结果 |
| 独立审查 | Agent B（受邀） | 待对方 | 接受后核对具体版本 | 审查消息 |
| 交付 | Agent A | 未开始 | 记录结果、限制和恢复入口 | 前两项核销或明确缺口 |

状态：未开始/进行中/待对方/暂搁置/已完成/已取消。新的轮次不继承旧角色、授权、游标或FIN。

## 请求、接受、交付、审查

时间换为工具实际时间，统一项目时区；ID必须唯一。

```text
[2026-10-05 10:00:00 +08:00] Agent A → Agent B：[id=a-demo-task-001] [type=TASK]
请独立审查产物/修复文件及测试结果，不并发修改实现文件；交付发现和未验证范围。

[2026-10-05 10:01:00 +08:00] Agent B → Agent A：[id=b-demo-accept-001] [type=ACCEPT] [reply_to=a-demo-task-001]
已读入口和规则，接受只读审查；声明本轮能力、启用、授权和角色，不宣称回复后持续在场。

[2026-10-05 10:03:00 +08:00] Agent A → Agent B：[id=a-demo-result-001] [type=RESULT] [reply_to=a-demo-task-001]
交付产物/修复文件；记录真实版本、SHA-256、测试结果和未验证项，请核对此版本。

[2026-10-05 10:05:00 +08:00] Agent B → Agent A：[id=b-demo-review-001] [type=REVIEW] [reply_to=a-demo-result-001]
记录实际读取版本、指纹、时间、发现及验证证据，不照抄实现者“通过”的结论。
```

用[原子锁模板](../references/checklists.md)追加消息；测试和等待在锁外。ACK只是已读，RESULT不是验证通过。实现方处理发现，版本变化须核对相关影响；记录者更新权威事项表，不覆盖历史消息。

## 结束与恢复

交接六项：完成项和证据、本人剩余独立工作、下一动作、需要谁、恢复入口、阻塞与未验证项。仍有可独立工作就继续做；缺审查时如实写缺口，不能代答。已核销请求不被旧“仍需要你”无限延期。归档按项目约定先存原文、回读再整理，同范围同锁。

收尾也须先满足其它前提，再检测连续五分钟无他方信息/推进；可用[窗口工具](tools.md)的`--window 300`，检测期间继续读新输入、巡检工作，有新工作先处理再计时。用户取消、完成与工具硬限制分别记录。
